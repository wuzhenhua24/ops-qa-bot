## 飞书源使用说明

部分组件的知识由维护人写在**飞书云文档**里（历史原因 + 免去定时同步），未落到本地 md。
这种情况通过两件事接进 bot 的检索流程：

1. **INDEX.md 标注**：上表"飞书源"列打 ✓ —— bot 路由到该组件后会知道要去看飞书源。
2. **`<组件目录>/feishu_docs.md`**：登记该组件相关的飞书文档，每条带"标题 / URL / 覆盖 / 更新于"。bot 用这个清单 + 用户问题做匹配，决定要不要调 `ask_feishu_doc` 工具拉飞书内容。

### feishu_docs.md 格式约定

每条飞书文档一个二级标题，下面跟三行属性。**"覆盖" 那一行是 bot 判断相关性的依据，必须写清楚这条文档管什么场景/关键词**，写得越具体 bot 命中率越高。

```markdown
# <组件名> 飞书文档索引

> 维护人：<姓名/open_id>。新增条目按下面格式补一段即可。

## <文档标题>
- URL: https://feishu.cn/docx/xxxxxxxx
- 覆盖：<这份文档讲了什么、适用什么场景；逗号分隔的关键词/短句>
- 更新于：YYYY-MM
```

参考实现见 `redis/feishu_docs.md`。

### 维护建议

- 一个文档一段，不要把多份文档塞一段里
- "覆盖" 写关键词而不是抽象描述："集群扩容、分片重平衡、新节点上线、回滚步骤" 比 "集群运维相关" 好
- 文档下线 / URL 变动了及时改 —— bot 不会自动校验链接
- 不要把答案抄进 `feishu_docs.md`，这里只是索引；答案在飞书原文里，bot 会通过工具去取

## 升级规则（找不到答案时）

bot 在文档里找不到答案时，应当：

1. 先回复 "文档中未找到相关内容" 加上简短说明
2. 根据问题归属判断对应组件，从上表里查到该组件的 `open_id`
3. 在答案末尾追加特殊标记：`<<ESCALATE:ou_REPLACE_WITH_REAL_ID_1:redis>>`（owner 后用 `:` 跟该组件的"目录"列；归档卡会落到该目录下的 `qa-archive.md`）
4. 如果跨组件或归属不明，用 `<<ESCALATE:none>>` 不 @ 任何人（不带目录）
5. **不要直接在文本里写 `@张三` 或 `@ou_xxx`** —— 系统会读 `<<ESCALATE:...>>` 标记自动渲染 @ 提醒

升级触发后，系统会在群里多发一张"问答归档"表单卡：负责人正常作答的同时把整理后的答案填进去提交，bot 自动追加到 `<对应组件目录>/qa-archive.md`，丰富后续可检索的文档库。这块完全由系统处理，bot 答题时无需关心。
